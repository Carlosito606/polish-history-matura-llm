# Polish history matura with small open LLMs (team Vibers)

An offline system and datasets that let a small open model (Bielik-4.5B) take the Polish history matura exam
(CKE, poziom rozszerzony, 60 points): a retrieval harness over the whole Polish Wikipedia, an essay pipeline with
fact checking, an open vision model that describes exam images, generated and verified training/evaluation data,
and blind-graded evaluation reports. Built during the **Warsaw Model Trainers** hackathon
(Kolektyw3, Warsaw, 25–27.09.2026).

**Result: 3rd place in the small-model category.**

## Data

The data was built for teaching and evaluating small open models on the Polish history matura. The code that
uses it (harness, Wikipedia knowledge base, evaluation) is in `code/`.

**Not included:** any CKE material (papers, answer keys, our transcriptions of CKE tasks, image descriptions of CKE
sheets). It is copyrighted; every row derived from it was filtered out. `scripts/fetch_cke.py` and
`scripts/fetch_arkusze.py` download the originals from the public CKE/OKE sites if you need them for evaluation.

## Contents

| Path | Rows | What |
|---|---|---|
| `qa/claude_wiki_verified/*.jsonl` | 3,446 | Matura-style questions generated by Claude from Polish Wikipedia articles and then verified by a second Claude pass against the article (`verified`, `verify_note`, `evidence`). Types: abcd 1163, open 774, pf 665, chrono 513, match 331 |
| `qa/zpe_verified/*.jsonl` | 562 | Same pipeline on openly licensed ZPE (Zintegrowana Platforma Edukacyjna) history elements — only elements whose own caption states CC BY / CC BY-SA / CC0. Types: abcd 191, open 136, pf 101, chrono 79, match 55 |
| `devsets/dev-[a-h].jsonl` | 552 | Held-out evaluation sets (same generator, different articles), balanced over eras; `smoke.jsonl` (51) quick check; `dev_all.jsonl` (219) a subset; `eval.py` the scorer (strict + lenient, fixed Tak/Nie bug) |
| `training/sft_v2_short_answers.jsonl.gz` | 4,389 | Chat-format SFT rows: system + user prompt (question + retrieved Wikipedia passages, exactly as our harness builds them) → **short canonical answer** ("B", "P, F, P", "C, A, D, B", "1-B, 2-A", a name/year) |
| `training/rft_v3_bielik_own_reasoning.jsonl.gz` | 2,276 | Rejection-sampling data: Bielik-4.5B-v3's **own** reasoning + "Odpowiedź: …" (k=4 samples at T=0.7, kept only when the final answer matched the gold; ≤2 per question). `meta` has n_correct_of_k, greedy_ok, context titles |

Row format of the QA files: `id, type, question (full Polish text incl. options/statements), answer (canonical),
accept (accepted variants), points, difficulty, source_title, source_url, evidence, verified, verify_note`.
Dev sets additionally carry `era`.

## What we learned (so you do not repeat it)

- Graded against the real CKE rubric on full papers, LoRAs trained on these sets (short answers, or the model's own
  reasoning) did **not** beat the untouched Bielik-4.5B on held-out CKE 2024/2026 papers, even though they gained a lot
  on these generated dev sets. The dev sets reward exact short answers; the matura rewards justified open answers and the essay.
- What did help: an essay pipeline with retrieval over Polish Wikipedia (+3.25/15 per essay over raw Bielik on 12
  papers, 3 blind examiners). The biggest losses are factual errors in dates and superficial arguments.
- Use full CKE papers with rubric grading as the primary metric from day one.
